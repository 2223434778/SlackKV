## 2. 补齐 terminal 语义：禁写也应避免无意义挤占

本轮store gate本身按预期工作。相邻问题在observe路径：
`slackkv_m1_observe` 先用完整输入向controller注册/更新需求、rebalance、reclaim_tails，之后 `prepare_store` 才识别terminal并禁写。

审查方独立执行原始controller的512块例子：
- A已加入、请求结束但会话未结束，目标512；
- 新的独立T以512块输入加入，实际请求已声明terminal，但该信号目前不传给controller；
- A目标立即变256，T目标256；
- T完成结束后A目标恢复512。

复现只运行逻辑控制器，未重放新native/GPU场景。结合native observe调用reclaim的源码可见：当A尾块可回收时，这条路径会为了一个不会存任何数据的请求去缩减A。当前GPU序列末尾的新terminal在其他会话已结束后发生，因此没有测试到这个反例。报告已提到terminal增长引起短暂缩额，应把这件事补完整。

要求最小修复，具体接口由执行侧选择：
- 新terminal-only会话应正常登记身份并最终结束，但不申请未来保留份额、不导致其他会话为它缩额。
- 已有会话最后一轮输入增长，不应仅因这次不会存的数据扩大其保留需求，或无意义轮转余数导致其他前缀回收。
- 保留当前请求可用的已存前缀，正常lookup/load和完成结算。不能提前end或把已有member目标直接归零再在lookup前回收。
- 将“请求的native身份路径”“未来保留需求”“在途读取保护”区分清楚；不要求重写整个控制器。
- 用上述新terminal加入反例和已有terminal增长各做一项CPU/native针对性验证；非terminal正常加入仍应缩额。这个修补不要求单独启动一轮性能矩阵。

这属于减少无效准入和回收，不应宣称已经解释了全部280MiB额外D2H；完整成本归因仍需事件记录。

## 3. 下一实现里程碑：共享system prefix + 独立后缀

当前任一共有块可能让后来的整个generation停止optional store。对常见共享system prompt，这会使独立前缀实验中的能力无法使用。下一步先支持一个明确的小范围：多个串行会话共享同一根system prefix，随后各自增长独立后缀。优先native接口和CPU验证，避免一开始实现任意分叉DAG、预测或GPU预取。

执行侧可以选择简单的多引用表/前缀树，不必另造物理KV缓存。至少满足：
1. 相同native身份的公共块只存一次、物理容量只计一次；session ID不替代内容身份，不用salt消除共享。
2. 共享公共前缀不导致整代写入被拒绝。每个会话仍能保留自己的连续私有后缀，并经原生路径恢复。
3. 一会话缩额/结束只撤销它的逻辑保留需要；不能删除其他存活会话依赖的公共祖先。保留中的后缀及pending/load引用都必须使必要祖先继续受保护。
4. 最后一个保留需要结束且物理引用结清后才释放；仍经过同一native policy/free/events与逐批物理容量检查。
5. 旧generation迟到完成、重复通知、store失败产生后缀等沿用已验证结算契约。不要直接删shared检测而继续使用单一key_owner。

一个可快速实现的受限方案是公共根前缀记一次物理成本、私有后缀分配剩余预算；应明确公共根本身只能按可负担的连续深度保留，不能无上限预留。也可采用满足目标前缀的key集合并集来计费，由执行侧选择更简单的方案。相同block大小下，物理预算针对distinct keys，不能直接累加各session逻辑前缀深度。逻辑保留需要与native DMA ref_cnt是两类引用，不应混为一谈。

不要求这个版本同时证明共享场景速度优势。先交付：
- 两个共享前缀会话均可存自己的后缀，不再一整个会话fallback；
- 容量不重复收费、A结束后B仍可恢复、最后释放干净；
- 一次共享根/不同私有marker的真实恢复检查（在已有授权范围内）。marker应放在各自私有历史中，确保串错后缀可被检测。

若无法用小改动安全实现，提交明确接口阻塞与最小设计取舍，不为了完成目标伪造共享支持。超出此受限形状的分支仍可显式fallback。独立路径M1/StaticFair保持可用，测试只覆盖被修改的生命周期与必要回归。
