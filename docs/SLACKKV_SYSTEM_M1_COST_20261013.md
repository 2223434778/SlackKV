# M1 有界成本定位：修复局部热点，停止当前动态变体调参

2026-10-13；交接基线 `5495a3636f6fb37196c6b9375a7abb4d0ba1d072`。最终实现版本为本报告所在提交。遵循 `RESEARCH_REVIEW_M1_SHARED_20261013.md`，不扩 M2/M3，不搜索参数或更换 workload。

## 结论

共享回收有真实 CPU 热点：大量受保护块各自重复遍历祖先。一个保持保护集合等价的提前停止条件，把 512 块保护状态的回收调用从约 9 ms 降到 0.375 ms。保留这项小修补。

但新 GPU 对照没有显示该修补改善整体关键路径：修正版相对原 M1 的 median E2E **+0.46%**、全序列 **+0.29%**。相对 root-aware StaticFair，median **−1.84%**，总 DMA **+93.52%**。这是各一次筛选，不能宣称差异显著、稳定收益或修补造成稳定退化。

因此停止当前“即时 max-min、可借就写”动态变体的性能优化。保留 opt-in 实现、terminal 与共享生命周期组件，以 root-aware StaticFair 作为工程参考。没有修改部署默认值，没有删除历史代码/结果，没有推出新在线策略。

## 预先冻结的范围与方法

先 CPU/native 计时；只有测到明显热点才修补，再做一次小型真实验证。原 M1、修正版 M1、StaticFair 沿用 `results/system_m1_shared/preparation5`：Qwen2.5-1.5B FP16、TP1、compiled、GPU KV 512 MiB / host 224 MiB、公共 root 512 tokens、四个独立私有会话、19 个正式请求、153088 输入 / 304 输出、四个 16K 压力请求。五个互不命中的形状预热，固定工具间隔 0.15 s，不清 GPU，三性能 run 均无详细状态日志且有相同两个 pool checkpoint。正确性另用 batch-invariant 模式，不混入性能比较。

GPU 顺序冻结为原 M1 → 修正版内容检查 → 修正版 M1 → StaticFair；原 M1 运行结束并清理后才上传修正版。只改 native 祖先遍历，controller、spec、请求输入、分配策略和终止语义不变。各 run 的 native/source SHA、命令和预算在原 family 的 `execution.json` 中。

## 已有事件：无用写入、重复写入和有效读取分开

从 content4 的 70 状态与 20 请求记录按 observe/request_finished 对齐，写入和最终回收均为 1228 块 / **537.25 MiB**：

| 请求 | 写入块 | 类型 | 可推断的重复写入块 |
|---|---:|---|---:|
| A0 | 512 | 首次填充 | 0 |
| B0 | 240 | 首次私有 tail 填充，共享 root 已存在 | 0 |
| S0 | 32 | 首次私有 tail 填充 | 0 |
| D0 | 160 | 首次私有 tail 填充 | 0 |
| A3 | 80 | 缩额后的扩额重写 | 80 |
| B-after-A-end | 204 | 扩额重写和新增 tail | 80 |

已知未复用的两个案例仍为 A 首次恢复前回收 **112 MiB**、B 末段扩额后仅 GPU 命中再结束的 **89.25 MiB**，合计 **201.25 MiB**。另可由同一私有前缀深度推断 **70 MiB** 重复写入；这些分类有重叠，不能相加。原始快照没有逐 key 时间线，具体 key 级生命周期归因与在途时间为 UNKNOWN；不声称 201.25 MiB 是性能 run 的完整额外 DMA 或可免费消除成本。

新旧 M1 的真实性能 run 均计算 108096 输入 tokens、GPU 命中 24512、host 恢复 20480，D2H 537.25 MiB、H2D 560 MiB；StaticFair 分别为 114624 / 24512 / 13952，D2H 185.5、H2D 381.5 MiB。M1 多付迁移换来少重算 **6528 tokens（正式输入的约 4.26%）**，不能将额外 H2D 全部称为浪费。

## CPU/native 计时与等价修补

CUDA 初始化显式禁止。真实 native 审计分别使用原函数和候选函数；29 组审计的返回结果完整一致，均有 75 次共享回收调用，累计原 0.9386 ms / 候选 0.9016 ms。审计多为小状态，不能用它推断实际 GPU 调度器的调用次数或时间。

另外在真实 native manager 中建立固定元数据状态，100 次/批、5 批，原/候选顺序交替；下表为批内平均调用时间的批间 median。每批前后快照严格一致，无回收事件和分配变化：

| 状态（512 host 块容量） | 原调用 ms | 候选调用 ms |
|---|---:|---:|
| 单会话，无保护引用 | 0.3353 | 0.3347 |
| 单会话，512 块 load 引用 | 8.9830 | 0.3749 |
| 单会话，512 块 pending store | 9.0102 | 0.3758 |
| 单会话，512 块本次 store 参数保护 | 8.9797 | 0.3695 |
| 四会话，无保护引用 | 0.4566 | 0.4557 |
| 四会话，A 当前驻留前缀 load 引用 | 1.5081 | 0.4753 |
| 四会话，D 全请求路径参数保护 | 2.8059 | 0.4898 |

四会话逻辑路径为 512/384/64/256 块，共享 root 32 块；物理块数、实际 targets、refs 和各批计时均保存。load/pending 在这些计时状态中人为保持，是真实 manager 的合成元数据实验，不是复制 GPU 调度频率。

修补仅在 `key in keep` 时停止祖先遍历。初始 needed 是已物化连续前缀的并集，已祖先闭合；每条新增保护链也补至根或已闭合链。因此保护集合相同，排序、物理引用检查、free-list、事件、pending/失败/结束/generation 语义均不变。避免保护块×深度的重复工作，仍保留每次 parents/depths 重建与物理排序，未引入缓存失效状态机。单个 needed 已覆盖的 512 块前缀，旧遍历访问 131328 次，新循环体 0 次。

候选等价比较后，实际安装版本再通过 29 组真实 CPU/native 审计。必要集合/事件/归档对照回归以及相关本地测试另见测试输出。没有声称所有并发、任意 DAG 或生产规模已验证。

## 真实 GPU 验证与负结果

## 关键路径判断与在线信号

原共享 M1 的全序列 9.7341 s，逐请求 E2E 合计 6.6519 s，压力请求约 3.3181 s，请求间约 3.0822 s，其中预设间隔 2.7 s。逐请求 E2E 仍含计算、调度、通信和驱动，不能直接称为纯模型计算时间。

原性能 run 的 CUDA event 传输合计：M1 D2H 27.345 ms、H2D 27.730 ms；Fair 13.256 / 26.075 ms；Full 61.611 / 20.337 ms。native `cpu/gpu_worker.py` 将 start/end CUDA event 毫秒转为秒，metrics 累加 operation 时间。它不提供请求阻塞或 DMA/计算重叠的分解，也不包括 CPU 准入等待。字节差很大，而这组报告的传输设备时间差约 15.7 ms；不能从字节量推导数秒 E2E 收益。

本轮证据支持：**局部 CPU 热点存在，但不是已确认的当前整体瓶颈；动态保留多节省的重算较少，并附带可观察的写回/回收成本。**真正阻塞的迁移、实际 CPU 调度器累计成本和纯计算占比仍 UNKNOWN。实际修补未改善 E2E，足以停止沿这一局部热点追求整体收益，不能推广为所有规模的 CPU 管理优化无效。

唯一考察的简单在线信号是“已有 host 复用证据才允许弹性份额”。A0 没有复用历史，可约束最初借用，但未来 B/S 加入未知，压低保留也可能损失首次恢复；B 后期扩额已有多次真实 host 复用，仍不会排除末次未复用 tail。未来的 B_end/GPU 命中不得用于当前准入。不证明该信号安全保留收益，也不实现或调阈值。已可见的终止信号由 terminal gate 处理；其他可在线确定无用的写入没有找到。

下一技术决策：静态公平前缀作为工程参考，动态 M1 留作功能组件；若重启算法研究，应先用有代表性的长期会话、真实到达/并发和更大模型检验复用生存期与可避免重算的收益空间。本轮不自动启动这些实验，不改变项目最终目标。本轮没有新算法创新成果，也没有新 NoHost/Compiled OnDemand 对照。
