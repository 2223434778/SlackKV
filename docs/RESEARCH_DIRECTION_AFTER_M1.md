**建议：暂缓新系统开发，等待“强公平前缀基线仍有明显、可在线避免的损失”的关键证据。** 收尾动态 M1，不开展 M2/M3，不继续小模型序列调参。保留 32B StaticFair 正结果；唯一保留的条件候选是异质长期会话的持久部分前缀价值分配，目前不足以立项系统 PoC，也不申请 GPU 验证。

## 2. StaticFair 为什么有效

本次 CPU 审计重新验证32B归档 **82文件/84,782,502原始字节**，核对三方法全部198请求、实际输入哈希、128输出/request、原始时戳和起止Prometheus计数。每方法输入1,863,168/输出8,448；资源、模型和执行条件沿用原冻结协议，没有调整容量或输入。证据：[evidence_verified.json](../results/research_direction_after_m1/evidence_verified.json)。

| 指标 | NoHost | Full | StaticFair |
|---|---:|---:|---:|
| Session E2E median s | 969.20 | 992.50 | 809.89 |
| 实际计算输入tokens | 1,863,168 | 1,863,168 | 1,338,880 |
| host恢复tokens | 0 | 0 | 524,288 |
| GPU缓存命中tokens | 0 | 0 | 0 |
| D2H GiB | 0 | 448.875 | 64 |
| H2D GiB | 0 | 0 | 128 |

Full 全量写入超过64GiB池多次，却没有兑现恢复。StaticFair 限制各会话连续初始前缀，上限20个12,480 tokens、最后一个12,544，合计262,144。每个会话之后两次续接，有限池保住这些前缀，总恢复恰好是容量的两倍。它既减少无效写入，又实际避免了 **524,288 tokens/28.14%** 的重复输入计算。机制收益来源是“保存能活到复用的前缀”，不是 JIT 把传输提前几十毫秒。

这是64GiB host和同一connector下 Full/Fair 更干净的准入对照。NoHost无connector，布局差异已记录。Full所有miss不能在缺少驱逐事件时归因于某一次LRU操作；一组三方法不是独立重复，21会话也不是21次实验。背景第三请求的首token到响应结束平均间隔代理相对NoHost **+16.94%**，不能用总吞吐遮蔽该代价。64GiB是明示服务预算，147GiB全部初始历史是合成保留目标，不是生产同时驻留量或真实需求下界。

## 3. 它还损失什么：可以计算，但不能混淆界的范围

### 固定持久前缀：均匀案例的额外 token 机会为零

限制为每个私有初始前缀**只首次写入并固定保留**，不补写、不换入新会话、不借助额外GPU驻留；目标仅是总复用token数。初始长度均28,672，每会话恰好两次复用，任意合法深度分配 `q_i` 的收益为 `2×Σq_i ≤ 2×262144 = 524288`。StaticFair 已达到这个界。CPU未来信息oracle以每块未来引用次数为权重、保持前缀连续性进行最优分配，同样得到524,288；小状态穷举回归验证这一计算。

因此，**把同一批持久前缀额度重新分给另一些会话，不能在这个模型中再增加总命中tokens**，并可能损害公平性。这个oracle甚至允许偏向少数会话，仍没有额外token收益。它不是全局延迟上界：非线性Prefill成本、排队、滚动写入/回收、GPU驻留和闭环到达变化均不在模型内。同样命中量仍可能有不同GPU时间和会话延迟；这部分目前未知。

### 无限存储参考：存在可复用重算，但不是同预算可达收益

按实际输入连续性，42个续接共有 **1,214,976** 个可复用此前输入tokens；假设无限可用旧KV、不计恢复与初始化成本，全部输入中仍必须计算 **648,192**（初次输入、真实扩展和背景）。StaticFair仍计算的可复用旧输入为 **690,688 tokens**。

这表明可复用重算没有消失，但**不能说新策略能省掉690,688，更不能把比例换算成E2E加速**。同预算固定前缀模型已饱和；要兑现更多必须证明另一种资源/时间安排能保留更多有效状态，且写入、回收、迁移和对其他Agent的代价可接受。147GiB全部初始root、实际GPU池约17.09GiB、host64GiB仅说明完整永久保留目标不适合这个容量，不证明某一在线策略必然胜出。

### 当前关键路径还不能归因

Fair的第1/2次续接TTFT median约 **298.0/261.1s**；这些包含排队、Prefill和加载，不能当计算时间。客户端输出阶段区间代理也不是逐Token TPOT或纯Decode。没有精确调度/迁移状态分解、`T_prefill(prompt_length,cached_depth)` 曲线、真实GPU/host重叠驻留或生命周期成本。因此：

- 更深前缀究竟多省多少GPU毫秒：**未知**。
- 跨tier重复占用、终止后的滞留是否明显限制此32B结果：**未知**，GPU hit=0不能证明GPU没有驻留。
- 同资源滚动检查点是否比强公平基线好：**未知**。
- 32B收益的独立run可重复性、现实开放到达SLO与强已有方法差距：**未知**。

M1已说明“逻辑份额增加”不等于“新增写入有价值”：小模型修补后相对原M1 median+0.46%，相对Fair仅−1.84%却DMA+93.52%。不能把32B剩余重算直接当作重新启动即时借用的依据。

## 5. 唯一条件候选：异质长期会话的持久部分前缀价值分配

**这是值得先否定的机会问题，不是已接受的新算法。** 问题是：在合理双层容量下，稳定前缀的复用次数、可保存长度和缺失Prefill成本显著不同时，简单公平保留是否仍浪费大量可避免GPU工作；能否只在确有兑现证据的新写入边界做价值选择，而不是每次扩额都写/缩额都回收。

- **适用场景：** 共享有限GPU/host、长期重复前缀、不同完整任务的调用数/前缀稳定性/计算代价异质。GPU热或host能完整覆盖重用工作集时，不需要这一机制。当前均匀32B三turn不能验证它。
- **简单方法何时不够：** 同字节前缀未必有同样未来兑现次数或可避免GPU成本；但在当前均匀案例，均分的token目标已经足够。必须先找到强公平基线实际错留的前缀，不能因为负载异质就宣称有性能损失。
- **在线可用信号：** 当前prompt/native前缀身份、与已完成历史的LCP、已发生调用及复用、当前tier命中/真实容量、已有复制时间、可靠任务完成信号。不得使用下一次调用时间、未来总turn数/最终GPU命中。历史复用会偏向已被服务的会话，反馈存在选择偏差；需要公平保护和bootstrap，不能将首次未命中判为低价值。
- **收益来源：** 减少无复用前缀占用/未兑现写入，把有限字节用于确能替代较贵重算的前缀；不是更大内存、减少真实工作量或让低优先Agent等待换来的收益。当前可实现收益数值**未知**。
- **可能的最小机制：** 公平的基础部分前缀加上基于过去兑现与已测重算成本的有限写入选择；不立即迁移/回收已保留份额，不预取。普通加权方法作为对照；若它已解决问题，就接受工程结果而不包装创新。本阶段没有实现该策略。
- **成本：** 首先一个小型离线分析；若证据成立，才考虑在现有native准入处做有限PoC。上线部分仍需引用/抢占/取消/公平语义验证，工程成本中等，不能当“一行打分”。复用M1的身份/物理引用/安全回收组件只为保证安全，不复用其即时max-min假设；无已测传输瓶颈，故不接入JIT/Lease/PSA/Frontier。
- **放弃条件：** 理想离线参考相对加强后的公平基线也几乎无剩余机会；或差异只靠未来信息/严重牺牲部分任务；或已发生信号无法区分复用；或强普通准入/加权方法已达到同样结果且无实质新约束；或迁移和实现成本超过可避免工作。满足任何一种，就不写系统。

不列第二个候选。压缩/量化需要KV内容和质量证据，tier互斥放置需要实测重叠与引用证据，当前均缺失；添加预测或更多调度机制也不能补上这些事实。

## 6. 一个最小验证方案：先 CPU 机会门槛，尚不申请 GPU

**负载：** 一个事先固定、包含完整任务生命周期的长历史多会话trace，保留真实输入身份、调用次序/依赖、输出工作量和工具事件。不按缓存收益选择任务，不裁掉长上下文/长输出。可先沿用现有公开hash代理的完整15条样本做结构机会检查，但不能将其直接作为Qwen性能负载。

本次该代理重算为2661请求、65个显式容器/model组，每组调用数median20/P95 220/max311；容器未证明是线性Agent。2476请求proxy输入超过32K，仅两个完整组在proxy输入+输出上满足旧32K，且**没有一个满足条件的组有至少3次调用**。因此不存在由本样本直接选择的完整旧栈多轮子集；proxy数也不是Qwen实token。数据缺少Qwen真实计算与物理命中，原endpoint时长不能填入A6000成本模型。必须先补一个完整可表示的任务族和成本证据；找不到就维持暂缓，不制造有利合成替代。

**对照：** 保留StaticFair，并在CPU模型中给它同样的shared-root去重、短需求饱和、可用结束信号和物理容量；以普通工作守恒公平前缀为加强参考。加入适用的EfficientAgent式准入及RR-tail策略模型，公开抽象/移植差别；不是先挑会thrash的Full来制造优势。普通加权保留同样作为朴素对照。离线未来信息oracle单独标注，只用于找机会，不与在线方法混为一谈。

**看什么：** 主要看强基线丢失的可复用前缀中，有多少在相同容量、前缀连续性和物理引用约束下本可保住；若有已测 `T_prefill(n,h)`，再换算为可避免GPU工作。现有proxy无原生refs，只能先给放松引用限制的乐观参考；缺失状态不能填为空闲或声称可行在线收益。固定记录到达也不重现策略改变后的闭环交错。没有曲线时只报告tokens，E2E继续未知。同步报告每任务损失、额外写入/回收字节和不公平集中损失，不能只看总hit。

**事先停止门槛：** 若未来信息理想参考都不能减少至少20%的基线“丢失的可复用输入tokens”，或收益依赖跨模型/未完成KV/不合法引用，结束该候选。20%是下一便宜筛选的token机会门槛，**不是E2E预测，也不回改旧验收**。即使超过门槛，若当前可见信号不能保住至少一半理想增量、或收益只在单个有利trace/牺牲其他任务出现，也不写PoC。通过只意味着再提交一个具体真实验证协议，不自动授权GPU。

**预计成本：** 获取/确认完整数据后，尽量复用现有CPU工具，限一个固定资源点和一个完整任务族，预计1–2人时、CPU回放以30分钟为上限、GPU为0；不是新框架/容量矩阵。当前缺负载映射及成本曲线，不给GPU小时或性能百分点的伪精确估计。本报告不申请预算，不动用M1余额。未来真实性能主指标仍应是匹配强基线的完整Session E2E，并保留每任务/背景和逐Token输出约束，而非以CPU理想hit宣称成功。

## 7. 此刻的决定与复现
