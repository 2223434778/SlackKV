Phase 3H extends the existing in-engine FirstTokenGate from one owner to a set of owners with a single run-wide request-specified capacity. A marked waiting resume is skipped only when the set is full. FIRST_TOKEN removes only its corresponding request from the set, so decode continues normally. The scheduler asserts if marked requests carry mixed limits and records gate_limit, gate_owner_request_ids, and the true owner-set size in SLACKKV_RESUME_TRACE. Connector-first native prefetch and ResumeAware promotion were reused unchanged.
